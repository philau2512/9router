# Kiro Stream Perf Harness (Phase 1)

Offline, credential-free profiling harness for the Kiro binary EventStream -> SSE
transform hot path. Every optimization phase in
`plans/260711-1001-kiro-stream-perf` is bracketed by a run of this harness.

## Files

- `stream-bench.mjs` - the runner. Replays a Kiro binary fixture through the real
  `KiroExecutor.transformEventStreamToSSE` and reports metrics.
- `gen-fixtures.mjs` - synthetic AWS EventStream fixture generator (no credentials,
  no network). Also importable (`buildKiroStream`, `buildFrame`).
- `fixtures/*.bin` - committed synthetic fixtures (plain / thinking / tools).

## Run

```bash
node tests/perf/gen-fixtures.mjs                                  # (re)build fixtures
node tests/perf/stream-bench.mjs --fixture=plain --repeat=5       # single-stream
node tests/perf/stream-bench.mjs --fixture=plain --concurrency=8  # stress (no I/O pauses)
node tests/perf/stream-bench.mjs --fixture=plain --concurrency=8 --io-sim-delay=1  # realistic
```

Flags: `--fixture=plain|thinking|tools`, `--repeat=N`, `--concurrency=N`,
`--io-sim-delay=<ms>`, `--slice-kb=N` (default 4), `--warmup=N` (default 2).

### Two concurrency modes (used for the Phase 6 go/no-go)

- **no delay** = worst-case CPU contention. All fixture slices are enqueued from
  memory with no yield, so transforms run back-to-back. Overstates event-loop
  pressure vs. production.
- **`--io-sim-delay=<ms>`** = realistic. Inserts a `setTimeout` between chunk
  enqueues to mimic network read pacing, letting the loop breathe between reads.

Use BOTH before deciding Phase 6 is warranted.

## Metrics

`cpuMs` is a **directional indicator only** — `process.cpuUsage()` has ~15ms
granularity on Win32, so short single-stream runs quantize hard. Use `wallMs` /
`throughputMBps` (from `performance.now()`) as the precision gate. `gcCount` /
`gcPauseMs` is the alloc-pressure proxy that Phase 2's buffer + decoder reuse
should move. Concurrency runs also report event-loop delay `p50`/`p95`.

## Fixtures

Committed fixtures are **synthetic** (generated by `gen-fixtures.mjs`) so CI and
new developers need no credentials. To capture a **real** upstream stream for
higher-fidelity numbers (one-time, developer machine, requires live Kiro creds):
tee the raw `result.response.body` bytes inside `kiro.execute()` when
`ENABLE_REQUEST_LOGS=true` to `tests/perf/fixtures/kiro-eventstream.bin` BEFORE
they enter `transformEventStreamToSSE`. Do NOT use `requestLogger.appendProviderChunk`
for the binary fixture: it fires after the binary has already been decoded to SSE
text and cannot be replayed into the binary parser.

## Baseline numbers (branch `test-upstream`, Win32, Node v24, plain fixture 444.5KB)

Captured with `--warmup=2`. `cpuMs` omitted (Win32 quantization).

| Scenario                                | Pre-Phase-2 | Post-Phase-2 | Delta       |
| --------------------------------------- | ----------- | ------------ | ----------- |
| single-stream, best warm wallMs         | 11.7 ms     | 10.3 ms      | ~12% faster |
| single-stream, throughput (mean of 5)   | 35.1 MB/s   | 37.9 MB/s    | +8%         |
| concurrency=8, total wallMs             | 107.8 ms    | 94.3 ms      | ~13% faster |
| concurrency=8, throughput               | 32.2 MB/s   | 36.8 MB/s    | +14%        |
| concurrency=8 --io-sim-delay=1, gcCount | 38          | 30           | fewer GCs   |

Phase 2 win is largest under concurrency, where the eliminated per-chunk
`new Uint8Array` realloc + per-frame `TextDecoder`/`TextEncoder` allocations cut
GC pressure that previously contended with I/O on the single event loop.

> Note: the single-stream throughput variance gate (<5%) is not reliably met on a
> noisy Win32 dev machine even with warmup (JIT + GC jitter on sub-15ms runs).
> Wall-time direction is consistent across every paired run; treat the <5% gate as
> aspirational on dev hardware and rely on the paired before/after direction.
